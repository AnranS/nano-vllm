NANO-VLLM / 从请求到 GPU

从一个请求读懂 nano-vLLM

先串起单 GPU 的一次生成，再逐步补上缓存、调度与执行优化。每章只解决一个问题。

第一阶段的目标

能解释：两个长度不同的请求怎么一起生成；其中一个结束后，另一个为什么还能继续；它们的 KV 存在什么地方。

先建立这一条主线

LLMEngine串起每一轮执行
→
Scheduler选请求、安排 token、分块
→
ModelRunner准备输入、调用 GPU
→
postprocess更新状态，回收请求

CPU 管理请求、块号与执行顺序；GPU 保存权重和 KV 向量，完成张量运算。ModelRunner 本身仍是 CPU 上执行的 Python 对象。

源码本身就是教材

nanovllm/ 一共约 1400 行，每个文件都写了逐段中文注释：类和方法说明它负责什么，行内注释解释那些"为什么要这么写"的地方——比如为什么 can_append() 判断余数等于 1，为什么捕获 CUDA Graph 要从最大档倒着来。

所以每章的读法是固定的两步：先读正文建立框架，再点开"查看源码"链接，顺着注释把这一段代码走一遍。快照页面带真实行号，点行号可直接定位并分享位置。只读正文不看代码，很容易停留在"大概知道"；只读代码不看正文，又容易在细节里迷路。

推荐的阅读节奏

  1. 第一遍 · 01—03请求主循环 → 调度器 → KV 分页。先能手算状态，不追 CUDA 内核。
  2. 第二遍 · 04—05前缀命中 → K/V 写入 → Attention 读取。把 CPU 块表和 GPU 数据接起来。
  3. 第三遍 · 06—07CUDA Graph / 编译 → 多 GPU 张量并行与通信。理解每项优化减少什么开销。
  4. 读完就做 · 08运行 CPU 小实验，验证分配、复用、回收和分块调度。

两种读法，按目的选

只想读懂机制

按 01 → 08 顺序读正文，每章配着注释过一遍源码。章末自检能答上来就继续，答不上来就回到那一节。

可以先跳过的：Triton kernel 的内部索引、flash-attn 的内部实现、CUDA Graph 的捕获机制。知道它们"负责什么"就够，第一遍不必知道"怎么做到的"。

想动手改代码

先跑通 example.py，再用"改一处、看什么变化"的方式读。几个适合练手的改动：

  • 把 kvcache_block_size 从 256 调到 512，看块数和前缀命中率怎么变。
  • 把 max_num_batched_tokens 调小，观察分块 Prefill 多出几轮。
  • 在 schedule() 里打印本轮 batch，构造一次抢占。
  • 给 SamplingParams 加 top-k，改 Sampler.forward ↗ L9。

读不下去的时候

数字对不上，九成是把"已经采样出来的 token"和"已经算过 KV 的 token"当成了一回事。回到 01 章那张手推表，逐行对 num_tokens 和 num_cached_tokens。

被"块"绕晕，说明逻辑块、物理块号、槽位三个概念混在了一起。回到 03 章的地址公式，拿具体数字走一遍。

GPU 部分读不动，先运行 08 章的 CPU 实验。它跑的是本仓库真实的 Sequence、BlockManager 和 Scheduler，不需要显卡，能把调度和缓存这条线单独跑通。

只需要这些前置知识

认识 Python 类、列表、字典和队列；知道 Transformer 从输入计算 Q/K/V，再预测下一个 token；理解 Prefill 处理输入、Decode 逐轮生成。遇到术语时查最后一章，不必先学完整套 CUDA。
